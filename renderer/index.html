修复分页 off-by-one：一行代码背后的边界思维

演示作者 2026-10-28 1,024 字

昨天下午，测试同学报了一个很刁钻的 bug：翻到第二页时，第一条数据总是和第一页的最后一条重复。排查了半小时，最后发现罪魁祸首是一行分页计算——页码从 0 开始还是从 1 开始，写代码的时候没对齐。

问题出在哪

接口约定页码从 1 开始，但内部的偏移计算仍按 0 开始写。当 page=1 时，offset 本应是 0，旧代码却跳过了前 size 条数据：

start = page * size          # 旧：第 1 页直接跳过 size 条
start = (page - 1) * size    # 新：与接口约定对齐

比修复更重要的

这行代码之所以能活到今天，是因为缺少边界测试。这次顺手补上了三个用例：第一页、恰好整除的最后一页、超出总页数的空页。以后谁再动分页逻辑，CI 会替我们盯着。

今天的提交一共 3 个：分页修复、补充边界测试、更新接口文档。改动不大，但值得记住一句话：约定要对齐在同一个地方，而不是散落在每个人的记忆里。
